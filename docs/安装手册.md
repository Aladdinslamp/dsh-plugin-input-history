## 1. 前置条件

```powershell
# Node.js ≥ 22（LTS 即可），Git（可选，用于 GitHub 安装通道）
node -v     # 本机：v24.14.1
npm -v      # ≥ 10.x
```

## 2. 安装 DSH 本体

### 方式 A：npm 全局安装（新机器推荐）

```powershell
npm install -g @deepseek-ai/dsh
dsh web    # 首次运行自动初始化 profile 并打开浏览器
```

### 方式 B：目录拷贝（本机现状）

本机 DSH 位于 `D:\tools\dsh`（含完整 `node_modules`，无需重新安装依赖），启动命令为：

```powershell
node D:\tools\dsh\node_modules\@deepseek-ai\dsh\lib\bin.js web
```

> 若 PATH 中已有 `dsh` shim，直接 `dsh web` 即可。迁移到新机器时**整目录拷贝** `D:\tools\dsh`，
> 并保证目标机器 Node 大版本一致（原生模块绑定 ABI），详见 §8。

## 3. 数据目录与模型配置

DSH 的全部用户数据在 **`$DSH_HOME`**（默认 `%USERPROFILE%\.dsh`，本机为 `C:\Users\zqs\.dsh`）：

```
C:\Users\zqs\.dsh
├── profiles\web\          # web profile（服务端+浏览器插件的装配清单）
│   ├── package.json       # 依赖与 dsh.profile.bundles（树外插件在此登记）
│   ├── cordis.patch.yml   # 用户自定义 patch 层
│   └── node_modules\      # 树外插件安装位置
├── sessions\              # 全部会话历史（JSONL）
├── settings.yaml          # 模型/提供方配置
└── credentials.yaml       # 凭据
```

模型配置示例（`settings.yaml`，按需修改）：

```yaml
llm-pi-ai:
  providers:
    zai-coding-cn:
      apiKeyEnv: ZAI_CODING_CN_API_KEY   # 密钥放在系统环境变量里
agent-default-model:
  provider: zai-coding-cn
  model: glm-5.3-flash
```

> 环境变量型密钥不随 `.dsh` 目录迁移，新机器需在「系统属性 → 环境变量」重新设置。

## 4. 启动 dsh web

```powershell
# 前台启动（首次启动会打印带 token 的 URL 并尝试自动打开浏览器）
dsh web
```

- 启动日志中的 `dsh web: http://127.0.0.1:3080/?token=...` 是本次进程的**认证地址**，
  用它打开一次浏览器取得 cookie，之后直接访问 `http://127.0.0.1:3080` 即可；
- **每次重启服务 token 都会变化**，重新从日志取；
- 后台启动（临时）：

```powershell
Start-Process -FilePath "dsh" -ArgumentList "web" `
  -WorkingDirectory "E:\prog" -WindowStyle Hidden `
  -RedirectStandardOutput "E:\prog\dsh-web.log" `
  -RedirectStandardError  "E:\prog\dsh-web.err.log"
Get-Content E:\prog\dsh-web.log -Tail 15    # 从这里取 token URL
```

长期驻留请用 §6 的 Windows 服务。

## 5. 安装 input-history 插件

> 功能：在 DSH 对话区输入框按 **↑ / ↓ / Esc** 回溯历史输入。
> 项目主页：<https://github.com/Aladdinslamp/dsh-plugin-input-history>

### 方式 A：从 npm 安装（推荐）

```powershell
dsh plugin --profile web add dsh-plugin-input-history
# 固定版本：
dsh plugin --profile web add dsh-plugin-input-history@0.1.2
```

CLI 自动完成：下载依赖 → 安装进 profile `node_modules` → 读取包内
`dsh.bundle.patch` 声明追加到 `dsh.profile.bundles` → 重启 `dsh web` 生效。

### 方式 B：从 GitHub 安装

```powershell
dsh plugin --profile web add github:Aladdinslamp/dsh-plugin-input-history
# 固定 tag：
dsh plugin --profile web add github:Aladdinslamp/dsh-plugin-input-history#v0.1.2
```

### 方式 C：本地目录安装（本机开发版，实际采用的步骤）

```powershell
# 1. 安装依赖到 profile（pnpm 在 profile 目录内执行）
cd C:\Users\zqs\.dsh\profiles\web
pnpm add "dsh-plugin-input-history@file:E:\prog\dsh-plugin-input-history"

# 2. 在 profile 的 package.json 中，把包名追加进 bundles 数组（CLI 不自动做）：
#    "dsh.profile.bundles": [ ..., "dsh-plugin-input-history" ]

# 3. 把包目录拷贝进 profile 的 node_modules（--force 被运行中服务锁住时的替代法）：
Remove-Item -Recurse -Force C:\Users\zqs\.dsh\profiles\web\node_modules\dsh-plugin-input-history -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Path C:\Users\zqs\.dsh\profiles\web\node_modules\dsh-plugin-input-history | Out-Null
Copy-Item -Path E:\prog\dsh-plugin-input-history\* -Destination C:\Users\zqs\.dsh\profiles\web\node_modules\dsh-plugin-input-history -Recurse -Force -Exclude node_modules
```

**包目录内必须存在的文件**（缺一即启动失败）：

| 文件 | 作用 |
|---|---|
| `cordis.patch.yml` | bundle 声明，**缺失则 `dsh web` 启动直接崩溃**（failed to read overlay） |
| `lib\client.js` | 浏览器半侧 bundle |
| `lib\index.js` | 宿主半侧入口 |

**生效条件**：客户端 bundle 只在服务启动时快照——**安装/更新后必须重启 `dsh web`**，并
Ctrl+F5 强刷页面。

### 卸载

```powershell
dsh plugin --profile web remove dsh-plugin-input-history
```

### 本 profile 的其他插件

| 插件 | 来源 | 作用 |
|---|---|---|
| `dsh-better-sidebar` | `github:omdsh-dev/DSH-better-sidebar` | VSCode 风格右侧边栏（资源管理器 / 终端 / Git / 浏览器），按会话隔离 |
| `dsh-remote` | npm `^0.8.14` | 远程机器 / SSH 相关能力插件 |

安装命令（二选一按来源）：

```powershell
dsh plugin --profile web add github:omdsh-dev/DSH-better-sidebar   # better-sidebar
dsh plugin --profile web add dsh-remote                            # dsh-remote（npm）
```

安装后 profile 的 `package.json` 应呈现：

```json
"dsh": {
  "profile": {
    "bundles": [
      "@deepseek-ai/dsh-base",
      "@deepseek-ai/dsh-web-app",
      "dsh-better-sidebar",
      "dsh-remote",
      "dsh-plugin-input-history"
    ],
    "patchReload": "live"
  }
}
```

## 6. 后台服务（WinSW）

用 WinSW 把 `dsh web` 注册为 Windows 服务：开机自启、崩溃自动重启。

### 6.1 准备

- 下载 [WinSW-x64.exe](https://github.com/winsw/winsw/releases)，放到 `E:\gitea`；
- 复制一份重命名为 `dsh-web-service.exe`（服务配置文件必须与 exe 同名）。

### 6.2 配置 `E:\gitea\dsh-web-service.xml`

```xml
<service>
  <id>dsh-web</id>
  <name>DSH Web</name>
  <description>DSH Web GUI 服务（http://127.0.0.1:3080）</description>

  <!-- 绝对路径，不依赖服务环境的 PATH -->
  <executable>D:\nodejs\node.exe</executable>
  <arguments>D:\tools\dsh\node_modules\@deepseek-ai\dsh\lib\bin.js web</arguments>

  <workingdirectory>E:\prog</workingdirectory>

  <!-- 显式指定数据目录（服务默认账户的 USERPROFILE 不同） -->
  <env name="DSH_HOME" value="C:\Users\zqs\.dsh"/>

  <logpath>E:\gitea\dsh-logs</logpath>
  <log mode="roll-by-size">
    <sizeThreshold>10240</sizeThreshold>
    <keepFiles>4</keepFiles>
  </log>

  <onfailure action="restart" delay="10 sec"/>
  <startmode>Automatic</startmode>
</service>
```

### 6.3 安装与启停（管理员 PowerShell）

```powershell
E:\gitea\dsh-web-service.exe install
E:\gitea\dsh-web-service.exe start
E:\gitea\dsh-web-service.exe status      # Started
E:\gitea\dsh-web-service.exe stop        # 停止
E:\gitea\dsh-web-service.exe uninstall   # 卸载服务
```

日志在 `E:\gitea\dsh-logs\`，token URL 从 `*.out.log` 里取。

> ⚠️ 服务与手动 `dsh web` **不能同时运行**（3080 端口冲突，后启动的一方会失败）。

## 7. 验证清单

| # | 检查 | 预期 |
|---|---|---|
| 1 | `dsh web` 启动无报错，3080 端口监听 | `Get-NetTCPConnection -LocalPort 3080 -State Listen` 有结果 |
| 2 | 浏览器打开带 token 的 URL 能进入对话页 | 页面正常加载 |
| 3 | 插件已挂载 | `dsh --profile web --dump-config` 含 `dsh-plugin-input-history`；或 DSH 设置 → 插件页显示"已启用/运行中" |
| 4 | 浏览器 bundle 已加载 | DevTools → Network 搜 `input-history` 有请求 |
| 5 | 功能 | 发消息 → 清空输入框 → **↑** 调出最新一条，气泡「历史 1/n」；↑↓ 翻页；Esc 恢复原稿 |

## 8. 排错速查

| 现象 | 原因与解决 |
|---|---|
| 启动崩溃：`failed to read overlay ... cordis.patch.yml` | bundle 清单里有包、包目录缺 `cordis.patch.yml` 或半安装。删除 profile 里该包目录，重新完整安装 |
| 改代码/装插件不生效 | 客户端 bundle 启动时快照——**重启 `dsh web`** 并 Ctrl+F5 |
| 服务启动后反复重启（WinSW wrapper 日志每几秒一次 Starting） | 服务环境找不到命令或端口被占：用绝对路径写 `<executable>`；先停掉手动实例 |
| `pnpm install --force` 报 `拒绝访问 (os error 5)` | 运行中的 dsh web 锁住了原生模块。先停服务再装，或用"删目录+整目录拷贝"方式更新 |
| profile 的 `package.json` 条目消失 | 编辑器保存了旧缓冲区；修改前关掉相关编辑器标签页 |
| 迁移新机器报 `NODE_MODULE_VERSION` 错误 | Node 版本与原机不一致——装回相同大版本的 Node.js |
| 按键无反应 | Network 搜 `input-history` 确认 bundle 加载；Console 查报错 |
| npmjs.com 页面 README 旧 | 展示层 CDN 缓存，不影响安装；以 `registry.npmjs.org` 数据为准 |

## 9. 一键完整安装脚本（从零 → DSH + 全部插件）

> 把下面整段保存为 `install-dsh.ps1`，在**管理员或普通 PowerShell** 中执行。
> 适用场景：新 Windows 机器从零装出与本手册一致的完整环境
> （DSH 本体 + dsh-better-sidebar + dsh-remote + dsh-plugin-input-history）。

```powershell
#Requires -Version 5.1
$ErrorActionPreference = "Stop"

# ===== 可按需修改的参数 =====
$WorkspaceDir  = "E:\prog"                    # dsh web 的默认工作目录
$InputHistoryVersion = "latest"               # input-history 插件版本（或 "0.1.2"）

# ===== 0. 环境检查 =====
Write-Host "==> [0/6] 检查 Node.js 环境..." -ForegroundColor Cyan
try { $nodeVer = (node -v) } catch { throw "未检测到 Node.js，请先安装：https://nodejs.com" }
Write-Host "    Node.js $nodeVer OK"

# ===== 1. 安装 DSH 本体 =====
Write-Host "==> [1/6] 安装 DSH 本体（npm 全局）..." -ForegroundColor Cyan
npm install -g @deepseek-ai/dsh
$dsh = (Get-Command dsh -ErrorAction SilentlyContinue).Source
if (-not $dsh) { throw "dsh 安装后仍不可用，请重开终端后再试" }
Write-Host "    dsh 位于: $dsh"

# ===== 2. 初始化 web profile =====
# 对 profile 的首次操作会自动从随附模板初始化 $DSH_HOME\profiles\web
Write-Host "==> [2/6] 初始化 web profile..." -ForegroundColor Cyan
dsh plugin --profile web list | Out-Null
$profileDir = Join-Path $env:USERPROFILE ".dsh\profiles\web"
if (-not (Test-Path $profileDir)) { throw "profile 初始化失败：未找到 $profileDir" }
Write-Host "    profile 就绪: $profileDir"

# ===== 3. 安装 dsh-remote（npm）=====
Write-Host "==> [3/6] 安装 dsh-remote..." -ForegroundColor Cyan
dsh plugin --profile web add dsh-remote

# ===== 4. 安装 dsh-better-sidebar（GitHub）=====
Write-Host "==> [4/6] 安装 dsh-better-sidebar..." -ForegroundColor Cyan
dsh plugin --profile web add github:omdsh-dev/DSH-better-sidebar

# ===== 5. 安装 input-history（npm）=====
Write-Host "==> [5/6] 安装 dsh-plugin-input-history@$InputHistoryVersion..." -ForegroundColor Cyan
if ($InputHistoryVersion -eq "latest") {
    dsh plugin --profile web add dsh-plugin-input-history
} else {
    dsh plugin --profile web add "dsh-plugin-input-history@$InputHistoryVersion"
}

# ===== 6. 校验 bundles 并启动 =====
Write-Host "==> [6/6] 校验配置并启动 dsh web..." -ForegroundColor Cyan
$manifest = Get-Content (Join-Path $profileDir "package.json") -Raw | ConvertFrom-Json
$bundles  = $manifest.dsh.profile.bundles
foreach ($expect in "dsh-better-sidebar", "dsh-remote", "dsh-plugin-input-history") {
    if ($bundles -notcontains $expect) {
        Write-Warning "bundles 中缺少 $expect，请手动检查 package.json"
    }
}
Write-Host "    bundles: $($bundles -join ', ')"

Start-Process -FilePath "dsh" -ArgumentList "web" `
    -WorkingDirectory $WorkspaceDir -WindowStyle Hidden `
    -RedirectStandardOutput (Join-Path $WorkspaceDir "dsh-web.log") `
    -RedirectStandardError  (Join-Path $WorkspaceDir "dsh-web.err.log")

# 等待端口就绪并打印 token URL
$deadline = (Get-Date).AddSeconds(60)
while ((Get-Date) -lt $deadline) {
    Start-Sleep -Seconds 2
    if (Get-NetTCPConnection -LocalPort 3080 -State Listen -ErrorAction SilentlyContinue) { break }
}
if (Get-NetTCPConnection -LocalPort 3080 -State Listen -ErrorAction SilentlyContinue) {
    Write-Host "`n✔ dsh web 已在后台启动（端口 3080）" -ForegroundColor Green
    Write-Host "  认证 URL 请从日志获取：" -ForegroundColor Yellow
    Get-Content (Join-Path $WorkspaceDir "dsh-web.log") | Select-String "dsh web:"
} else {
    Write-Warning "60 秒内 3080 未就绪，请查看 $WorkspaceDir\dsh-web.err.log"
}
```

**脚本说明**：

- 每一步失败会立即中断（`$ErrorActionPreference = "Stop"`），已完成的步骤不受影响，修复后重跑即可（各 `add` 命令幂等，重复安装会报已存在，忽略或先 `remove` 再装）；
- 第 2 步不启动完整服务、只触发 profile 初始化，因此整个脚本跑完后才有第 6 步这一次真正启动；
- 若 npm 注册被 Cloudflare 验证卡住导致 `npm install -g` 失败，见 §8 与《npm发布教程.md》的网络层建议；
- 停止后台实例：`Stop-Process -Id (Get-NetTCPConnection -LocalPort 3080 -State Listen).OwningProcess`。
